## 📖 功能简介

本插件是为 [AstrBot](https://github.com/AstrBotDevs/AstrBot) 设计的一款高级语音合成工具。它能将 LLM 的文本回复无缝转换为带有多样情感的语音消息，赋予您的机器人更加生动和个性化的表达能力。

- **两种语音化模式**：
    1.  **固定情感模式**：使用预设的默认或切换后的情感进行语音合成。
    2.  **自动情感识别模式**：调用LLM分析文本情感，并自动匹配最合适的声音进行合成。
- **长文本加速 (v1.2.0 新增)**：独有的句子切分与并行合成技术，能将长篇回复拆分，并发请求至多个TTS服务器，最后无缝拼接，大幅缩短长语音的等待时间。
- **动态情感管理**：通过指令自由注册、删除、查看不同的声音情感。
- **高度可配置**：支持自定义翻译API (OpenAI/Gemini)、TTS服务器地址和默认角色。
- **手动合成**：提供指令，可绕过 LLM 直接将指定文本合成为语音，方便测试。
- **LLM 主动语音工具**：当用户明确要求“说一句听听”“发段语音”这类需求时，LLM 可主动调用工具直接发送一条语音，不影响日常自动触发策略。
- **故障转移**：支持配置多个TTS服务器，一个失效时自动尝试下一个。
- **可配置触发频率**：支持每次触发、按时间间隔触发、按随机概率触发，降低聊天时的语音打扰。
- **翻译调试日志**：可选择将原文和最终合成文本写入 AstrBot 日志，方便排查翻译链路。
- **参考音频泄漏防护 (v1.8.0 新增)**：识别并拦截 Genie 后端偶发的「参考音频 + 本次语音」叠加结果，异常偏长时自动重试并保留正确的那份。
- **状态持久化 (v1.8.0 新增)**：会话/群语音开关、自动情感模式、各会话选择的角色与感情会自动保存，重启 AstrBot 后不用重新 `/tts-w`。
- **一键自检 (v1.8.0 新增)**：`/tts-status` 直接给出开关状态、当前音色是否可用、合成统计，并并发探测每台 TTS 服务器的连通性、延迟与可用角色。
- **重发上一条语音 (v1.8.0 新增)**：`/tts-again` 重发最近一条语音，不再消耗 TTS 算力。
- **WebUI 语音合成工作台 (v1.9.0 新增)**：AstrBot WebUI 的插件页里就能试听合成、批量管理感情、改配置、探测服务器、开关会话语音；内置 6 套 galgame 主题与舒适 / 紧凑双密度，偏好跟随账号保存。
- **感情包导入导出 (v1.9.0 新增)**：一条指令把整套音色导出成 JSON，换机器人或分享给朋友时直接导入；支持三种合并模式与「试运行」预演，服务端还能存多份快照随时回滚。
- **语音截断防护 (v1.9.2 新增)**：拦截 Genie 采样偶发提前结束导致的「话没说完就突然结束 / 中间少一整句」，明显偏短时自动重合成，并在成品末尾补一小段静音抵消播放端吃掉尾帧。v1.9.3 把根治的重抽做进了 Space 的 decode 层（快到几乎免费，默认 13 次尝试），插件侧则在后端整段返回空音频时自动再抽一次。
- **合成链路日志 (v1.9.5 新增)**：工作台新增「日志」页，把每次合成的 LLM 原文、翻译结果、真正送进 TTS 的文本、命中的参考音频、**情感是 LLM 选的还是关键词兜底的**、耗时与失败原因全串起来；再按「角色 · 情感」按失败率排序，一眼看出哪些情感需要换参考音频。纯内存缓冲，不写盘。
- **注意**：该服务默认合成日语，但支持通过配置或注册指令合成其他语言（需模型支持）。

## ⚠️ 重要前置：部署语音服务

本插件**自身不进行语音合成**，它依赖一个后端的 **Genie TTS 服务**。您必须先拥有一个可访问的该服务，插件才能正常工作。

> **Genie TTS** 是一个强大的语音合成项目，您需要将其部署为一个Web服务。
> - **官方仓库**: [https://github.com/High-Logic/Genie](https://github.com/High-Logic/Genie)

### 方案一：使用 Hugging Face 一键部署

算力免费而且无需本地机器配置，但是合成速度比较慢。

1.  **复制我的 Space**:
    -   服务仓库: [https://huggingface.co/spaces/clown145/genie-tts-t/tree/main](https://huggingface.co/spaces/clown145/genie-tts-t/tree/main)
    -   点击页面右上角的 **"Duplicate this Space"** 即可一键复制，拥有一个完全属于您自己的、免费的TTS服务。

2.  **使用自定义模型**:
    -   默认服务会从示例模型仓库 [clown145/my-genie-tts-models](https://huggingface.co/clown145/my-genie-tts-models/tree/main) 下载模型。该模型仓库已包含多个预置角色，例如： `kisaki` (月社妃), `hiy` (和泉妃爱), `may` (椎名真由理), `aoi` (葵) 等，您可以直接使用。现在默认注册三个角色是kisaki,aoi,oka。您可以去app.py按照说明修改。
    -   若要使用您自己的模型，请将您训练和转换好的模型上传到您自己的 Hugging Face 模型仓库，然后在 Space 的 `app.py` 文件中修改 `REPO_ID` 和 `CHARACTERS` 字典。
    -   **【关键步骤】** 在您的空间中，**您必须创建一个名为 `reference_audio` 的文件夹**，并将所有用于注册情感的参考音频文件（如 `.wav`, `.ogg`）放入其中。
    -   **注意：** Genie 服务目前有加载3个模型的上限，请确保 `CHARACTERS` 字典中启用的角色不超过3个。
3.  **开启自动保活（可选）**：Hugging Face Space 超过 24 小时无人访问会休眠。插件新增了“自动保活空间”的开关，开启后会定时访问空间主页防止休眠。配置项：
    -   **启用**：在插件配置中打开“是否自动定期访问 Hugging Face Space 以防止休眠”。
    -   **保活地址**：默认使用 TTS 服务器列表的第一个地址，若您想单独设置，请填写“保活请求的目标地址”。
    -   **间隔**：可通过“两次保活之间的间隔分钟数”调整访问频率，建议 15-30 分钟。

### 方案二：本地或 Windows 部署

- 如果您想在本地运行，请参照 Genie 官方仓库的文档进行部署。
- 作者还提供了 **Windows 一键整合包**，极大简化了部署流程，详情请访问其 GitHub。

**部署完成后，请记下您的服务 URL (例如 `https://your-name-your-space.hf.space`)，后续配置插件时需要用到。**

| **语音工具提示词** | 自定义约束 `genie_tts_speak` 何时可调用的 Prompt。支持 `{character}` 与 `{emotions}` 占位符；插件还会根据“外语TTS准备方式”自动补充：工具里该传原文，还是传翻译后的文本。 | (见默认值) |

| **Provider 翻译提示词** | 仅在 `provider_translation` 模式下生效，用于普通翻译场景。 | (见默认值) |

### 外语语音的推荐思路

对于日语这类外语语音，建议只在下面两种模式里选一种，不要混着开：

1. **`llm_injection`**  
   主 LLM 直接在回复末尾生成 `$...$` 翻译；如果你还开启了情感标签注入，也会一并生成 `[emotion=xxx]`。  
   这种模式下，`genie_tts_speak` 工具也会被提示“把翻译后的文本直接传进 `text` 参数”。

2. **`provider_translation`**  
   不给主 LLM 注入翻译标签，改由 AstrBot Provider 或外部翻译 API 负责翻译。  
   这种模式下，`genie_tts_speak` 工具可以直接传原文，插件会在发送前先翻译再请求 TTS。

### 性能配置 (v1.2.0 新增)
| 配置项 | 说明 | 示例 |
| :--- | :--- | :--- |
| **启用句子切分功能** | 是否开启长文本并行合成。可显著加速。 | `false` (默认) |
| **每个语音分段的句子数** | 数字越小，并行度越高，请求越频繁。请根据您的TTS服务器数量调整。 | `2` (默认) |
| **用于切分句子的正则** | **(高级)** 用于识别句子边界的正则表达式。默认已兼容中英文标点。 | `([。、，！？,.!?])` |
| **分段间停顿** | (v1.8.1) 开启句子切分后，分块拼接时按上一段的结尾标点补回停顿：句末标点/省略号补满，逗号顿号补一半，切在句中不补。0 表示不补。 | `260` (默认，毫秒) |
| **语音文本长度上限** | 超过该字数的部分**不会被朗读**（展示的文字不受影响），截断点优先选句末标点。设太小会让长回复的后半段完全没声音，设太大则分块多、排队久。`0` 表示不限制。 | `300` (默认，字符) |

### 日志与诊断 (v1.9.5 新增)

这一组只影响 WebUI「日志」页的数据来源。全部是**内存里的环形缓冲，不写盘**，重载插件即清空。四项都需要重载插件才生效。

| 配置项 | 说明 | 示例 |
| :--- | :--- | :--- |
| **运行日志采集** (`enable_run_log`) | 总开关。开启后插件会记下自己打的日志和每次合成的完整轨迹（LLM 原文、选中的情感与来源、耗时、失败原因）。关掉后日志页为空，也不再占内存。 | `true`（默认） |
| **运行日志条数** (`run_log_capacity`) | 内存里最多留多少条插件日志，超出丢最旧的。范围 50~5000。 | `500`（默认） |
| **合成记录条数** (`run_log_synth_capacity`) | 内存里最多留多少条合成记录。情感统计只统计还在缓冲里的记录，想看更长的趋势就调大。范围 20~2000。 | `200`（默认） |
| **记录完整文本** (`run_log_full_text`) | 开启时保存 LLM 原文与送进 TTS 的完整文本（单条上限 4000 字），方便逐字核对。关掉只留前 160 字摘要，省内存。 | `true`（默认） |

### LLM 主动语音工具

当用户明确提出“说句话听听”“发段语音”“念给我听”这类要求时，LLM 可以主动调用 `genie_tts_speak` 工具，直接向当前会话发送一条语音。

- 这个工具不会替代平时的三种自动触发模式。
- 它更适合一次性的“来段语音试听”场景。
- 工具调用的发送方式由 **LLM工具输出模式** 单独控制，默认是纯语音。
- 插件会把当前角色的可用情感注入给 LLM，引导它调用工具时填写 `emotion_name`，减少总是落回默认情感的情况。
- 工具文本里若误带 `[emotion=xxx]` 或 `$...$`，插件也会尝试解析并清理后再送入 TTS。
- 合成前会自动补齐句末标点，降低后端分句时尾音被截断的概率。
- 如果当前 **外语TTS准备方式** 为 `llm_injection`，主 LLM 会被提示先把内容翻成目标语言，再调用工具。
- 如果当前 **外语TTS准备方式** 为 `provider_translation`，工具可以直接传原文，插件会负责翻译。
- 工具发送过语音后，插件会自动跳过本轮普通自动 TTS，避免同一轮回复重复发两次声音。

### 💡 典型使用流程

1.  **部署服务与配置**：按照前述步骤部署Genie TTS服务，并在AstrBot WebUI中正确填写 **TTS 服务器地址列表** 和 **翻译API** 信息。
2.  **注册情感**：使用 `/注册感情` 指令添加至少一个您想用的情感。对于一个角色，注册的情感越丰富，自动情感识别的效果就越好。<br>
    `示例: /注册感情 kisaki 开心 reference_audio/Kisaki_happy.ogg ほら、ホタルもとても喜んでいます。`
3.  **设置默认值**：回到 WebUI 配置，将“默认角色名”和“默认情感名”设为您刚刚注册的，并保存。
4.  **选择模式并开启**：
    *   **自动情感模式** (推荐)：发送 `/tts-w`。现在，机器人的LLM回复将自动分析情感并使用最匹配的语音！如果想换个角色，使用 `/sw-w <新角色名>`。
    *   **固定情感模式**：发送 `/tts-llm`。回复将使用默认或通过 `/sw` 指定的固定情感。
5.  **开始对话**：享受带声音的机器人对话吧！
6.  **关闭模式**：发送 `/tts-q` 即可恢复发送纯文本。

### 💡 进阶技巧
如果感觉机器人回复长文本时语音等待时间较长，可以尝试在插件配置的 **“性能配置”** 中开启 **“启用句子切分功能”**。这会显著提升长语音的合成速度，尤其是在您配置了多个TTS服务器时。理论上添加的tts服务器越多，合成长文本越快，虽然tts服务本身似乎也有切分功能，但受限于抱脸免费空间的性能，合成长文本速度还是较慢。

遇到「不发语音了」「一直失败」时，先发 `/tts-status`：它会告诉你开关有没有开、当前角色/情感有没有注册成功、每台 TTS 服务器是否连得上（Hugging Face Space 休眠唤醒需要 1~3 分钟）。

## 📦 感情包：换机器人 / 分享音色

感情包是一份自描述的 JSON（`format: genie-tts-emotions`），内容是「角色 → 感情 → 参考音频路径 / 对应文本 / 语言」的完整映射。裸的 `emotions.json` 也能直接导入。

**三种合并模式**

| 模式 | 别名 | 语义 |
| :--- | :--- | :--- |
| `merge` | `合并`、`skip` | **默认**。只补齐缺少的条目，同名冲突保留现有的。 |
| `overwrite` | `覆盖`、`update` | 同名条目用感情包里的内容覆盖。 |
| `replace` | `替换`、`清空`、`force` | 先清空现有感情库，再整包写入。 |

任何模式后面都能再加 `试运行`（或 `dry`、`--dry-run`），只报告「会新增 / 更新 / 跳过 / 移除多少条」而不落盘：

```
/感情导入 overwrite 试运行
/感情包恢复 emotions-2角色.json replace 试运行
```

- 导入前逐条校验：参考音频路径必须是模型仓库内的相对路径（不接受绝对路径与 `..`），语言只认 `jp` / `zh` / `en`，不合法的条目会被跳过并在摘要里列出。
- 写入 `emotions.json` 采用「临时文件 + 原子替换」，失败自动回滚，不会写坏原文件；成功后立即生效，不用重启 AstrBot。
- 服务端快照存放在 `data/plugins_data/astrbot_plugin_genie_tts_llm/emotion_packs/`。`/感情导出` 会自动存一份，也可以用 `/感情包保存 我的音色.json` 手动存档，之后用 `/感情包` 查看、`/感情包恢复` 回滚。
- 同样的事情在工作台的「感情包」视图里都能点：导出下载、粘贴导入、试运行预览、快照恢复与删除。

## 🛠️ 故障排查

### 语音里出现「上一条语音 + 这次的语音」

v1.8.0 之前，让 Bot 主动发语音时偶发一条语音里先播上次的内容、再播这次的内容。

根因在 Genie 后端 `genie_tts/Core/Inference.py` 的 `GENIE.t2s_cpu()`：结尾用 `y[:, -idx:]` 取生成结果，而当模型第一步就输出 EOS（把 `……`、`。` 这类纯标点单独分段时必然发生）时 `idx == 0`，`y[:, -0:]` 会退化成整个序列，把参考音频的 prompt token 一起解码出来，于是听起来就是「完整参考音频 + 本次语音」。

本版本从三处解决：

1. **后端修复（推荐）**：Hugging Face Space 侧已按 `prompts` 实际长度切片、限制最大 token 数、无有效语义 token 时直接报错。用本仓库推荐的 Space 模板的用户请同步更新自己的 Space。
2. **不再制造触发条件**：插件不会再把纯标点/表情段落送去合成，句子切分时会把不可发音的碎片合并进相邻句子。
3. **插件侧兜底**：**参考音频泄漏防护**（默认开启）会在结果时长量级异常时丢弃并重试，日志中可见 `疑似参考音频被拼入结果`；`/tts-status` 的「参考音频泄漏拦截」计数可以看出它触发过几次。

### 语音结尾被切掉，或者中间少了一整句

表现是「最后一个字没说完就突然结束」，偶发、同一句话重发一次又正常。

根因在 Genie 的 T2S 采样：ONNX 推理没有固定随机种子，同一个句段有相当高的概率在第一步就输出结束符，这一段合成不出任何内容，服务端只记一行日志就把它跳过了。落在最后一段就是尾音被切，落在中间就是一整句凭空消失，整条消息只有一段时就是「叫它发语音却什么都没发出来」。实测单次退化率可以到 **60%** 左右，而且完全随机——重抽一定有效，关键只在于重抽够不够便宜、次数够不够多。

处理顺序：

1. **更新 Space（根治）**：v1.9.3 的 Space 端把重抽做在 decode 层——encoder / BERT / 参考音频 SSL 只算一次，之后只重跑解码，退化的那一次在解码第 1 步就退出，所以一次重抽只要约 2s，默认给到 13 次尝试（`GENIE_T2S_DECODE_RETRIES`）。用本仓库推荐模板的用户请同步更新自己的 Space。句段级的重合成（`GENIE_SEGMENT_RETRIES`、`GENIE_SHORT_RETRY_S_PER_CHAR`、`GENIE_SHORT_RETRY_MIN_CHARS`）仍然保留，作为 decode 层之外的第二道。
2. **确认 Space 是不是还是旧版**：看 `/tts-status` 的「后端空结果重试」。这一项只在非 0 时出现，非 0 就说明后端整段合成失败过——插件已经自动重抽了一次把语音救回来，但反复出现就是该更新 Space 了。新版 Space 的日志里能看到 `T2S recovered on decode attempt N/13` 这样的行；一直没有这种行、却反复出现空结果，就是 `app.py` 没更新。
3. **插件侧兜底**：**语音截断防护**（默认开启）会在结果明显偏短时重合成一次，日志中可见 `疑似句段被漏掉或尾音被截断`；`/tts-status` 与 WebUI 工作台的「截断拦截」计数能看出它触发过几次。
4. **只是最后一个字发虚**：那多半是播放端把尾帧吃掉了（QQ 会把 WAV 转成 silk）。把 **尾部补静音** 调大一些，比如 `300`。

### 长回复念到一半就停了（不是偶发，每次都在差不多的位置）

和上一节不是一回事。上一节是随机的、重发就好；这一节是必然的，同一段长文本每次都在同一处停住，而且停住的位置正好是文本里的某个逗号或句号。

原因是 **语音文本长度上限**（`tts_max_text_length`）：超出上限的文本会被直接丢掉、根本不会送去合成。它只影响朗读，`audio_and_text` 模式下发出来的文字仍然是完整原文，所以看起来「字都在、就是没念完」。

1. 先看 `/tts-status` 的「文本超长截断」计数，或 WebUI 工作台侧栏的「文本超长」格子。只要不是 0，就是这个原因。
2. 调大 **语音文本长度上限**。默认 `300`（v1.9.2 之前是 `150`，长回复很容易撞上），填 `0` 表示完全不限制。
3. 不建议直接填 `0` 又开着句子切分：一条超长消息会被拆成很多块排队，首句延迟会明显变长。先按实际回复长度往上加一档更稳。
4. WebUI 工作台的「流水线预览」可以直接看到某段文本会在哪里被截断、后面多少字不会被朗读，不用真的合成一遍。

### 语音像一口气念完，没有停顿

停顿由 Space 侧插入：句末标点默认 260ms、省略号默认 420ms（Space 端可用环境变量 `GENIE_SENTENCE_PAUSE_MS`、`GENIE_ELLIPSIS_PAUSE_MS`、`GENIE_MAX_PAUSE_MS` 调整），也可以开启 **自定义停顿标记** 后在文本里用 `[pause=600]` 精确插入。

如果听起来完全没有停顿，按顺序排查：

1. **开着「启用句子切分功能」**：v1.8.1 之前，分块拼接会让分段边界的停顿归零，整条语音像一口气念完。升级后由 **分段间停顿**（`chunk_gap_ms`，默认 260ms）补回；想恢复旧行为设为 `0`。
2. **Space 版本较旧**：v1.8.1 同时修掉了「行首或独立成行的省略号丢停顿」和「中间分段合成失败时吞掉停顿」，这两项在 Space 的 `app.py` 里，需要同步更新 Space。
3. **文本本身没有句末标点**：Space 靠标点判断停顿位置，LLM 回复不带 `。！？` 时无处可停。这种情况用 `[pause=ms]` 手动插入最可靠。

### 不知道 bot 为什么用了这个情感 / 想知道哪些情感容易失败

打开工作台的 **▤ 日志** 页（v1.9.5 新增，需要 `运行日志采集` 开着，默认就是开的）：

- **合成记录**：点开任意一条，能同时看到 LLM 的原话、翻译结果、真正送进 TTS 的那串文本、命中的参考音频与参考文本、**情感是 LLM 自己选的还是关键词兜底的**、当时给 LLM 的候选情感有哪些。情感不对时对着这几项就能分清是「LLM 选错了」「候选列表里根本没有合适的」还是「参考音频配错了」。
- **情感统计**：按「角色 · 情感」聚合并按失败率倒序，排在最前面的就是最该改的那几个情感 —— 通常是参考音频太短、或者参考文本和音频对不上。
- **运行日志**：级别选「只看问题」，能一次看完所有 WARNING 以上的记录（超时、泄漏拦截、截断补偿、翻译失败…），比在 AstrBot 控制台里翻要快得多，因为这里只收本插件自己的日志。

筛好之后可以「导出 .txt」把当前这批带走，方便贴到 issue 里。数据只在内存里，重载插件就没了，所以要留证据记得先导出。

### 重启后开关全没了

v1.8.0 起默认开启 **开关状态持久化**，会话/群开关与音色选择会写入插件 KV 存储。若你的 AstrBot 版本较旧、不支持插件 KV 接口，插件会自动降级为旧行为（重启重置），日志中会有提示。

### 一直合成失败 / 一直超时

先发 `/tts-status` 看服务器探测结果：

- 全部 ❌：地址填错、Space 被休眠（免费 Space 唤醒需 1~3 分钟），可开启 **启用 Space 保活**。
- ✅ 但延迟很高：免费 CPU Space 正常表现，建议开启 **句子切分** 或配置多台服务器。
- 「当前音色: ❌ 不可用」：`/查看感情` 确认角色与情感是否注册成功，参考音频路径必须是模型仓库里 `reference_audio/` 下的相对路径。

### WebUI 工作台打不开 / 插件页空白

- **AstrBot 版本过旧**：不提供插件页与 `register_web_api` 接口时，启动日志会出现「当前 AstrBot 不支持 register_web_api，WebUI 工作台已跳过」，升级 AstrBot 即可（v4.25 已验证可用）。
- **页面能打开但接口全报错**：确认启动日志里出现过「Genie TTS: 已注册 28 个 WebUI 工作台接口。」；没有则说明注册阶段就失败了，日志会带上原因。
- **切换主题后刷新又变回去**：工作台运行在受限 iframe 中，没有 localStorage 权限，主题与密度偏好保存在插件 KV 里；若你的 AstrBot 不支持插件 KV，偏好只在当前页面生效。
- **点「下载 .json」没反应**：浏览器拦截了 iframe 内的下载，允许一次即可；也可以改用「预览 / 复制文本」把内容复制走。
- **点标签不切换，八个分区全堆在一页**：v1.9.0 的样式表 bug，v1.9.1 已修。AstrBot 每次请求都从磁盘现读插件页资源（响应带 `Cache-Control: no-store`），所以升级后不用清缓存，但已经开着的插件页仍然跑着旧代码 —— 离开这个页面再进来（或刷新一次 WebUI）即可。
